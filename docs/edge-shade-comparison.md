# 道路区間の日陰率方式比較

## 目的

道路中央点1点の二値判定を、部分日陰を0〜100%で表せる方式へ置き換えるため、5m・10m間隔サンプリングを影との線分交差長と比較した。

## 固定条件

- 道路: 加工済みOpenStreetMap歩行グラフ、10,262エッジ、`EPSG:6676`
- 影: 加工済みPLATEAU LOD1建物、現行の凸包押し出しモデル
- 中心: 34.2325, 135.1917（和歌山駅周辺）
- 日時: 2026-08-11 14:00 JST
- 実行環境: Python 3.12.13 / Windows
- 実行コマンド: `.venv\Scripts\python.exe scripts\compare_edge_shade.py`

交差長方式は現行影モデル内の幾何学的な比較基準であり、現地の正解値ではない。

## 結果

| 方式 | 道路判定時間 | 平均絶対誤差 | 最大絶対誤差 | 部分日陰エッジ |
|---|---:|---:|---:|---:|
| 中央点 | 0.126秒 | 0.070651 | 0.954289 | 0 |
| 5mサンプリング | 1.364秒 | 0.009395 | 0.249077 | 2,226 |
| 10mサンプリング | 0.783秒 | 0.016072 | 0.751022 | 1,966 |
| 交差長 | 67.468秒 | 0 | 0 | 2,486 |

- 5m方式は中央点方式に比べて平均絶対誤差を約86.7%削減した。
- 5m方式は10m方式より0.581秒遅いが、平均絶対誤差は約41.5%小さい。
- 交差長方式は5m方式の約49倍遅く、全道路・多数時刻の事前計算には負荷が大きい。
- 5m方式の平均サンプル数は11.721点/エッジ、合計120,280点だった。

## 保存容量の目安

各エッジの日陰率をfloat32で保存すると、1時刻分は41,048 bytes（0.039 MiB）。5分刻みで24時間分を保持した場合、値だけで11.274 MiBとなる。ファイル形式の索引・メタデータと圧縮効果は含まない。

## 判断

次の事前計算方式には5mサンプリングを採用する。検索時に全道路を計算せず、地域・日時・影モデル版をキーとする加工済み日陰率を読む。交差長方式は代表ケースの評価基準として残し、通常経路探索には使わない。

画面の既定方式はこのタスクでは変更しない。次のIssueで、5〜10分刻みの生成・保存・検証・キャッシュ無効化を設計した後に統合する。

## 限界

- 1日時点だけの比較であり、太陽高度が低い時間帯や異なる季節をまだ評価していない。
- 道路形状とPLATEAU影の位置誤差、地形、樹木、庇、複雑な屋根は評価対象外。
- 最大誤差は短い影区間や境界形状の影響を受けるため、現地検証前に安全性を断定しない。
