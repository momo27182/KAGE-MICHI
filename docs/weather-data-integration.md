# 公式WBGT・警戒情報の取得とキャッシュ

Issue #39で実装した、環境省「熱中症予防情報サイト」の機械可読データを取得する境界です。公式の地点WBGTと公的発表は、異なるデータ型・異なる取得クライアントとして扱います。

## モジュール

- `kage_michi.weather`: 依存のないデータ型、Protocol、20分TTLキャッシュ、障害を吸収するサービス
- `kage_michi.infrastructure.moe_weather`: HTTPS通信、再試行、公式JSON・CSVの解析
- `scripts/check_moe_weather.py`: 現在の公式WBGT APIとの手動疎通確認

## 保持する情報

WBGTは値だけでなく、予測・推定実況・実測地点の実況というAPI上の種別、品質コード、基準時刻、対象時刻、取得時刻、出典URL、欠測・期限切れ状態を保持します。実測地点でも欠測時に推定値で補完されるため、種別だけで実測と断定せず品質コードを併記します。予測値はAPI仕様どおり10倍整数を℃へ換算し、実況値は小数の℃をそのまま扱います。

警戒情報は地域、通常／特別の別、発表・未発表・特別警戒判定中・運用時間外・訓練・試験、発表時刻、対象期間、取得時刻、発表版を保持します。公式の発表状態とキャッシュの鮮度は別フィールドです。フラグ2の「特別警戒情報判定」は発表済みとして扱いません。

## キャッシュと障害

- 同一の地点・種別・対象時刻・発表版は20分間再利用します。
- WBGT予測は基準時刻から90分、実況は対象時刻から60分を超えると`stale`です。
- キャッシュ期限後の更新が失敗した場合、最後の成功値を`stale`へ変更して返します。
- 成功値がない状態で取得に失敗しても、`OfficialHeatInformationService`は例外を画面向け問題文へ変換し、経路機能を止めません。
- 運用期間外、欠測、未発表、通信失敗は別の状態です。
- APIが成功応答でも0件の場合は「問題なし」とせず、値のない`missing`データとしてUI層へ渡します。
- WBGTクライアントには年度の情報提供地点マスタで確認した運用開始日・終了日を設定します。期間外は通信せず`outside_operation`を返し、年度更新時に設定も更新します。
- 通信は5秒タイムアウト、最大3回、0.25秒からの短い指数バックオフが既定です。

## 手動疎通確認

公式サービス運用期間中に、プロジェクトルートで実行します。

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe scripts\check_moe_weather.py --point 65042 --region 300000
```

地点番号65042と府県予報区等コード300000は和歌山です。年度ごとの情報提供地点マスタと公式地域コードで、番号と運用期間を再確認してください。コマンドは件数、サンプル値、値種別、品質、各時刻、状態、出典URLだけを表示し、取得データを保存しません。

## 安全上の注意

- 電子情報提供サービスの情報を利用していることと出典URLを表示します。
- 「公的発表なし」を「安全」と言い換えません。
- 本データは公式情報や医療判断の代替ではありません。
- 公的発表と地点WBGTを一つの独自危険度へ合成しません。
- サービス側の訂正・配信漏れがあり得るため、取得時刻と期限状態を必ず併記します。
