# ハッカソン版の画面機能棚卸し

更新日: 2026-08-11
関連Issue: [#11](https://github.com/momo27182/KAGE-MICHI/issues/11)

## 目的と調査範囲

ハッカソン版にあった機能を、見た目だけでなくデータ依存、計算負荷、安全上の注意まで含めて整理し、新しい軽量版へ戻す順序を決める。

調査の基準は次の順とする。

1. `archive/hackathon_2025/github_main_snapshot/app.py`: 当時のGitHub `main`にあった最終Streamlit版
2. `archive/hackathon_2025/app_realtime.py`: ローカルに残る後期版
3. `archive/hackathon_2025/shadow_navi.pptx`: 18枚の発表資料
4. その他の`app*.py`と初期検証スクリプト: 機能の由来と変遷の確認用

アーカイブは証跡として保持し、直接変更しない。

## 画面機能の一覧と移行判断

| 機能 | ハッカソン版の動作 | 依存データ・処理 | 既知の問題・リスク | 判断 |
|---|---|---|---|---|
| 日付・時刻指定 | 日付、時、10分単位の分を入力し、その時刻の影を計算 | Pysolar、建物ポリゴン、高さ | 日時変更のたびに全建物の影と経路を再計算。JSTからUTCへの変換処理も明示性が低い | **移行済み**。軽量版で日時入力、タイムゾーン、再計算単位を明示済み |
| 出発地・目的地の緯度経度入力 | サイドバーで座標を入力 | ローカル道路グラフ、最近傍ノード | 一般利用者には扱いにくい | **移行済み**。開発・フォールバック入力として維持 |
| 地名検索 | 「和歌山駅」等を入力し候補を検索、選択して地点を設定 | Geopy / Nominatimの外部通信 | 候補順位・重複排除・対象範囲判定がない。タイムアウト以外の障害や利用制限への対応が弱く、特定地点が出ない | **再設計**。検索Issueで候補品質、範囲、失敗時表示、キャッシュを設計 |
| 地図クリックで地点設定 | スタート/ゴールモードを選び、地図クリックで即反映 | streamlit-folium、最近傍ノード | クリックのたびに`rerun`し、影・経路・地図を再生成するため重い。意図しないクリックも即確定する | **再設計**。クリック取得と「確定・計算」を分ける |
| 日陰優先ルート | 日向区間へペナルティを加えた経路を表示 | 影ポリゴン、NetworkX、道路グラフ | 道路中央点だけで日陰判定。グラフの重みを画面処理中に更新 | **移行済み（現行方式）**。計算とUIを分離済み。区間日陰率への改善は別Phase |
| 最短ルートとの比較 | 初期検証と発表図で、赤い最短経路と青い日陰優先経路を併記 | 同じ道路グラフで`length`と日陰コストを比較 | 最終Streamlit版では表示されなくなり、距離増と日陰改善のトレードオフが見えない | **再設計して復活**。比較指標と凡例を含む独立TODOを追加 |
| 経路指標 | 距離、徒歩時間、日陰率、日向距離を表示 | 経路エッジ長、中央点日陰判定。徒歩速度80m/分固定 | 日陰率は区間率ではない。徒歩時間は固定速度で推定 | **一部移行済み**。距離・日陰率・計算時間は実装済み。徒歩時間は仮定を表示して復活 |
| コンビニ・給水地点 | OSMのコンビニと飲料水地点を取得し、表示切替 | OSM featuresの外部取得 | アプリ起動時の通信が重い。鮮度・網羅性・名称表示・出典表示が不足 | **再設計**。ローカル取得物として分離し、出典・更新時刻・凡例を表示 |
| 手動気温と暑熱アドバイス | 20〜40℃を手入力し、気温と日向距離の独自閾値で「安全〜危険」と助言 | 手入力値、独自条件分岐 | 公的な熱中症警戒情報ではない。湿度・WBGT等を使わず、安全情報と誤認される恐れ | **そのまま移植しない**。Phase 5で公的情報源、更新時刻、地域、出典を伴って再設計 |
| 1時間後との比較 | 1時間後の影と経路を再計算し、日陰率差から待つ/出発する助言 | 影計算と経路探索をもう一式実行 | 処理が重い。23時台の日付繰越表示が不十分。日陰率だけで「涼しい」と断定している | **再設計して復活**。時間帯別前計算後に、別時刻との比較として実装 |
| 日向ペナルティ調整 | スライダーで日陰優先度を変更 | 経路コスト | 数値の意味が一般利用者に伝わりにくい | **保留**。開発者向け設定または「距離優先／バランス／日陰優先」に置換 |
| 地図表示状態の維持 | 中心座標とズームをsession stateに保存 | streamlit-folium | 再描画負荷は解決しないが操作感には必要 | **直接移行可能**。クリック再設計時に導入 |
| リセット | 出発地・目的地と検索候補を初期化 | Streamlit session state | 特段なし | **直接移行可能**。地点入力の再設計時に導入 |
| 涼しさを意識した画面デザイン | 青系テーマ、カード、アイコン、注意表示 | CSS / Streamlit | 派生版が多数あり保守対象が曖昧。表示文言の安全性確認が必要 | **段階的に移行**。単独の旧版コピーではなく新画面の共通スタイルへ統合 |

## 共通する技術的課題

- 起動時にOSMから道路、建物、コンビニ、給水地点をまとめて取得しており、通信と前処理が画面起動を塞いでいた。
- 画面のトップレベルで全建物の影を生成・結合し、地点・時刻・クリックによる再実行のたびに重い処理が走る構造だった。
- 影判定は道路エッジの中央点だけで、区間全体の日陰率ではない。
- 建物高さ欠損は一律10mで、PLATEAUは未導入。地形、樹木、庇、複雑な屋根等も扱わない。
- 地名検索は外部サービスへ都度問い合わせ、候補品質、利用制限、障害時処理、対象地域の検証が不十分だった。
- 地図クリックの入力イベントと重い計算が直結し、プロットしにくさの原因になっていた。
- 暑熱表示は手入力気温と独自閾値で、公的警戒情報、WBGT、観測・予報時刻、出典を備えていなかった。
- 「1時間後は涼しい」という文言は日陰率差のみからの推測で、気象条件を含まないため表現を改める必要がある。
- 派生版が単一ファイルのコピーとして増え、UI、データ取得、影計算、経路探索が密結合だった。

## 実装順序

1. **完了**: OSM取得とローカル読込を分離し、影計算と経路探索を分離、軽量画面へ接続する。
2. **次**: 地名検索を再設計し、対象範囲とエラーを利用者に明示する。
3. 地図クリックを「仮置き→確定→計算」に分け、クリックだけでは重い計算を起動しない。
4. コンビニ・給水地点をローカルデータとして準備し、出典・更新時刻付きで表示する。
5. 最短ルートと日陰優先ルートを比較し、距離増・日陰改善・推定徒歩時間を説明する。
6. 時間帯別の日陰情報を前計算した後、現在と別時刻の経路・日陰率を比較する。
7. PLATEAUと区間日陰率で精度を上げる。
8. 公的な気象・暑熱情報を、出典・地域・更新時刻・利用上の注意とともに統合する。

## 棚卸しで追加すべきTODO

既存TODOには、地名検索、地図クリック、コンビニ・給水地点、公的な暑熱情報の再導入が登録済みだった。一方、発表資料と初期実装で価値が確認できた次の2件は独立した完了条件が必要なため、開発TODOへ追加する。

- **最短ルートと日陰優先ルートを比較表示する**（Phase 2 / P1）
- **現在と別時刻の経路・日陰率を比較する**（Phase 4 / P1。時間帯別前計算の後）

## 安全情報の境界

本プロジェクトが計算する影、日陰率、徒歩時間、経路は推定値であり、医学的な安全保証ではない。熱中症警戒情報を画面へ載せる際は、環境省・気象庁等の採用する一次情報源、対象地域、発表・更新時刻、取得失敗時の扱いを仕様化する。ハッカソン版の独自ラベルや助言文は正本にしない。
