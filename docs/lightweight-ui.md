# 軽量Streamlit画面

最終更新: 2026-08-11

## 目的

加工済みOSMデータと分割済みの影・経路計算を利用し、検索操作のたびにOSM取得や不要な再計算を行わない最小画面を提供する。

## 再計算境界

| 変更した入力 | データ読込 | 影計算 | 経路探索 |
|---|---:|---:|---:|
| 変更なし | 再利用 | 再利用 | 再利用 |
| 出発地・目的地・日向ペナルティ | 再利用 | 再利用 | 再計算 |
| 出発日時 | 再利用 | 再計算 | 再計算 |
| データディレクトリ・manifest更新 | 再読込 | 再計算 | 再計算 |

データは`st.cache_resource`、影と経路はそれぞれ`st.cache_data`で独立して保存する。キャッシュキーの依存関係はUI中立の`recalculation_keys`でも表現し、自動テストで固定している。

## 表示内容

- 経路線、出発地、目的地
- 経路距離、推定日陰率、推定日向距離、表示処理時間
- 対象日時、計算実行時刻、データ取得処理日時、対象範囲
- OpenStreetMapの出典
- 推定値であること、高さ欠損10m、凸包影、道路中央点判定という限界

## 実データ測定

2026-08-11、和歌山駅周辺の加工済みデータと夏季午後の代表ケースで`measure_ui_cache.py`を実行した。Streamlitのbare modeによる同一プロセス内キャッシュを使用している。

| 操作 | 合計時間 | 結果 |
|---|---:|---|
| 初回 | 5.723秒 | データ1.005秒、影4.270秒、経路0.449秒 |
| 同一入力を再表示 | 0.007秒 | データ・影・経路を再利用 |
| 目的地を変更 | 0.389秒 | データ・影を再利用し、経路だけ再計算 |

同一入力のキャッシュ後は数秒以内、地点変更後は1秒以内という目標を満たした。一方、未計算日時へ変更した場合は影を再計算するため、2秒目標はまだ保証できない。時間帯別日陰率の事前計算と影生成高速化は後続タスクで扱う。

## 起動と測定

```powershell
.\.venv\Scripts\python.exe -m streamlit run src\streamlit_app.py
.\.venv\Scripts\python.exe scripts\measure_ui_cache.py
```

`data/prepared/wakayama-station`はGit管理対象外であり、存在しない環境では先に`prepare_osm_data.py`を実行する。
