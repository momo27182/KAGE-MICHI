# ADR 0004: 事前計算した道路日陰率をNPZとJSON manifestで保存する

- 状態: 採用
- 決定日: 2026-09-24

## 背景

10,262道路区間を5分刻みで再計算すると画面応答を妨げる。時刻・道路キー・日陰率を高速に一括読込でき、入力版や破損を検出できる形式が必要である。

## 決定

- 数値配列はNumPyの圧縮NPZ、追跡情報はJSON manifestへ保存する。
- 道路は並べ替えた `(u, v, key)` で固定し、日陰率は0〜1の`float32`とする。
- manifestに地域、タイムゾーン付き期間、5分間隔、5m間隔、CRS、入力SHA-256、影モデル版、出力SHA-256、意味チェックサム、件数、性能値を持たせる。
- 一時ディレクトリで完成させた後に原子的に公開し、既存出力は上書きしない。
- 夜間は `daylight=false` と `shade_ratio=1.0` の組で「直達日射なし」を表し、建物日陰とは区別する。

## 理由

NPZは現在の依存関係だけで利用でき、`float32`の二次元配列を圧縮してまとめて読める。CSVより型と形状を保ちやすく、Parquetや専用DBの新規依存も不要である。人が確認する追跡情報をJSONへ分離することで、成果物を開かず版とチェックサムを確認できる。

## 影響

- アプリ起動中の高価な影生成と道路判定を、日単位のオフライン処理へ移せる。
- 日付・地域ごとの生成と配布が必要になり、対象期間が増えるほど保存容量も増える。
- NPZは部分行読込向けではない。対象規模や期間が大幅に増え、読込目標を満たせなくなった場合はZarrやデータベースを再評価する。
- UI統合時は `daylight` を必ず参照し、夜間を「建物の日陰」と表示してはならない。
