# ADR 0002: OSM加工済みデータをGraphML・GeoPackage・JSONで保存する

- 状態: 採用
- 決定日: 2026-08-10

## 背景

ADR 0001で、検索時のOSM取得をやめ、投影・整形済みデータを事前生成すると決定した。保存対象にはNetworkXの属性付き道路グラフ、GeoPandasの建物・地点、出典・取得条件があり、ローカルで確実に往復保存できる形式が必要である。

## 決定

- 道路グラフはOSMnxが標準対応するGraphMLで保存する
- 建物と地点は座標系と属性を保持できるGeoPackageへ個別に保存する
- 出典、取得処理日時、対象範囲、座標系、既定高さ、件数、ファイル名、SHA-256をJSON manifestへ保存する
- manifestを最後に書き、ローダーは全ファイルの存在とSHA-256を確認してから読み込む
- 生成物は`data/`配下に置き、通常のGitコミットには含めない

## 理由

GraphMLはOSMnxのグラフ属性を専用APIで保存・復元できる。GeoPackageは追加依存を増やさず、GeoPandasから投影済みベクターデータを保存できる。JSON manifestを分けることで、データを開かなくても追跡情報と整合性を確認できる。

## 検討した代替案

- OSMnxのHTTPキャッシュをそのまま使う: 復元・投影が残り、キャッシュ後でも3.22秒かかった
- GeoParquet: 高速化の可能性はあるが、現環境では追加の`pyarrow`依存が必要
- すべてGeoPackage: 道路グラフのNetworkX属性を完全に往復する追加処理が必要
- pickle: 簡単だが、Python依存が強く、信頼できないファイルの読込リスクもある

## 影響

- 実データのローカル読込は0.85〜1.15秒となり、キャッシュ後3秒目標内に入った
- 複数ファイルを一組として管理する必要がある
- 形式変更時はmanifestの`schema_version`を更新し、移行処理を用意する
- 将来GeoParquet等が明確に速いと確認できた場合は、このADRを置換する
