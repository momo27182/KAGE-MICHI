# 技術判断記録

後から変更コストが高くなる設計・技術判断を、ADR（Architecture Decision Record）として保存します。

## 記録する判断

- データ形式、データベース、API、フレームワークの選定
- 影計算、日陰率、経路コスト、暑熱指標の方式
- オフライン前処理、キャッシュ、タイル化の設計
- 性能と精度の重要なトレードオフ
- セキュリティ、プライバシー、ライセンスに関する判断

細かな実装方法や一時的な試行は `log.md` に残し、すべてをADRにはしません。

## ファイル名

`NNNN-short-title.md` の形式にします。

例: `0001-precompute-road-shade-ratios.md`

## テンプレート

```markdown
# ADR-NNNN: 判断の題名

- 状態: 提案／採用／廃止／置換
- 日付: YYYY-MM-DD

## 背景

何を解決する必要があるか。

## 判断

何を選択したか。

## 理由

なぜその選択をしたか。比較した代替案も書く。

## 影響

利点、欠点、性能、精度、運用、移行への影響。

## 根拠

測定値、検証結果、Issue、Pull Request、Notion、データ出典へのリンク。
```
