# ADR 0005: 公式WBGTと熱中症警戒情報を別データとして扱う

- 状態: 採用
- 決定日: 2026-09-25

## 背景

ハッカソン版には気温の手入力と独自の暑熱表示があった。本格版では安全に関わる情報の根拠、時刻、品質が追跡でき、公式発表とアプリの計算結果を混同しない構成が必要である。

## 決定

- 地点の暑熱指標は環境省「暑さ指数」公開Web APIのWBGTを使う。
- 公的発表は環境省の熱中症警戒情報CSVを使う。
- 公的発表と地点WBGTは別のデータモデル、別の表示領域で扱い、一つの独自危険度へ合成しない。
- 予測・推定実況・実測実況、品質、欠測、運用期間外、期限切れを区別する。
- 発表時刻、対象時刻、取得時刻、出典を常に保持する。
- 気温、湿度、風、日射等から独自WBGTや独自の「警戒アラート」を初期実装では作らない。

## 理由

環境省の情報は公式のWBGTと警戒情報を機械可読形式で提供し、値の種別、品質、発表状態を追跡できる。公式WBGTは暑熱に関係する気温、湿度、日射等を既に考慮しており、アプリ側の簡易再計算より根拠と運用が明確である。公的発表は広域、地点WBGTは局地に近い値で役割が異なるため、統合せず並べる方が誤解を抑えられる。

## 影響

- 次Issueで2種類の取得クライアントとデータ契約が必要になる。
- 外部サービス停止時も経路機能を止めず、最後の成功値は期限切れとして表示する。
- 年度ごとの運用期間・仕様更新を確認する運用が必要になる。
- 気象庁アメダスは将来の補助表示候補とし、未文書化Web JSONには依存しない。
- UIには「発表なしは安全を意味しない」「公式情報や医療判断の代替ではない」と表示する。
