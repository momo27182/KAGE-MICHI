# 気象API・暑熱指標の選定

- 調査日: 2026-09-25
- 対象: Phase 5「気象・暑熱評価」Issue #37
- 結論: 初期実装は環境省の公式WBGT Web APIと熱中症警戒情報CSVを採用し、公的発表と地点WBGTを別の情報として表示する

## 目的

KAGE-MICHIで暑熱情報を扱う前に、根拠、時刻、品質、障害時の意味を明確にする。これは情報源とデータ契約の選定であり、APIクライアント、キャッシュ、画面、経路コストの実装は次Issueへ分離する。

## 採用する情報と役割

### 1. 公的発表

環境省の熱中症警戒情報CSVを使う。発表内容をアプリ独自判定へ変換せず、次をそのまま保持する。

- 通常の熱中症警戒アラートと熱中症特別警戒アラートの別
- 対象地域、発表時刻、対象日、発表状態
- 発表なし、運用時間外、訓練、試験、取得不能の別
- 出典名と参照URL

通常の警戒アラートは、予報区内のいずれかの地点で日最高WBGTが33以上と予測される場合に発表される。特別警戒アラートは、都道府県内の全ての情報提供地点で日最高WBGTが35以上と予測される場合が基準である。公的発表がないことを「安全」と読み替えない。

### 2. 地点の暑熱指標

環境省の暑さ指数Web APIを使い、WBGTを初期の暑熱指標とする。

- 予測値、推定実況値、実測実況値を区別する
- 品質コードと欠測を保持する
- 発表・基準時刻、対象時刻、取得時刻を保持する
- 地点名・地点コードと、経路からの距離を表示可能にする

屋外WBGTは湿球温度、黒球温度、乾球温度を組み合わせた指標で、公式推定にも気温、湿度、風、日射等が使われる。初期実装で気温等から独自WBGTを再計算しない。

### 3. 初期対象外の項目

- 気温・湿度・風: 将来の参考表示候補。独自の危険度判定には使わない
- 日射量・雲量: 公式WBGTと役割が重なるため初期対象外
- 降水量: 日陰とは別の経路快適性機能として将来検討
- 独自の「熱中症警戒アラート」: 作成しない

## データ契約案

公的発表と地点WBGTを一つの危険度へ統合しない。

### `OfficialHeatAlert`

| 項目 | 内容 |
| --- | --- |
| `source_id`, `source_url` | 情報源識別子と参照先 |
| `region_code`, `region_name` | 公的発表の対象地域 |
| `kind` | `heat_alert` / `special_heat_alert` |
| `status` | `issued` / `not_issued` / `outside_operation` / `training` / `test` / `unavailable` |
| `issued_at` | 発表時刻（タイムゾーン付き） |
| `target_start`, `target_end` | 対象期間 |
| `retrieved_at` | アプリ取得時刻 |
| `publication_id` | 訂正や新版を識別する値 |

### `OfficialWbgtReading`

| 項目 | 内容 |
| --- | --- |
| `source_id`, `source_url` | 情報源識別子と参照先 |
| `point_code`, `point_name` | 観測・予測地点 |
| `latitude`, `longitude` | 地点座標 |
| `value_celsius` | WBGT値（℃） |
| `value_kind` | `forecast` / `estimated_actual` / `measured_actual` |
| `quality_code` | 公式品質情報。意味を失わず保存する |
| `reference_at`, `valid_at` | 基準時刻と対象時刻 |
| `retrieved_at` | アプリ取得時刻 |
| `status` | `current` / `stale` / `missing` / `unavailable` / `outside_operation` |

すべての時刻はタイムゾーン付きで保存し、画面では日本時間を明示する。

## 更新・キャッシュ・障害方針

- 同一地点・種別・対象時刻の通常キャッシュは20分を初期値とする。
- WBGT予測は基準時刻から90分を超えたら`stale`候補とし、対象時刻そのものも併記する。
- WBGT実況は観測時刻から60分を超えたら`stale`とする。
- 警戒情報は一律20分で失効させず、対象日、発表版、次の公式発表で更新する。
- 取得失敗時は最後の成功値を時刻付きで残せるが、必ず`stale`表示にする。
- 運用期間外、欠測、未発表、通信失敗を同じ「情報なし」にまとめない。
- 更新直後へのアクセス集中を避け、公式マニュアル記載の更新時刻から少しずらす。
- リトライは短い指数バックオフとし、経路検索自体は暑熱情報なしでも利用可能にする。

数値の期限は初期運用値であり、次Issueの実測と公式運用変更に合わせて設定可能にする。

## 画面の安全表現

表示は少なくとも次の2区画に分ける。

1. **公的発表**: 発表名、対象地域、対象日、発表時刻、出典リンク
2. **地点WBGT**: 値、予測・推定・実測の別、地点、対象時刻、取得時刻、品質・期限切れ状態

固定文言:

- 「公的発表なし」は「安全」を意味しません。
- 周囲の建物、舗装、日射、活動量、体調により実際の暑さは異なります。
- 本アプリは公式情報や医療上の判断の代替ではありません。

環境省の観測地点は標準化された環境であり、建物脇や舗装面など経路上の局所環境と一致しない。そのため、公式WBGTとKAGE-MICHIの日陰率は並べて提示し、合成した医学的安全判定を出さない。

## 利用条件・運用上の確認

- 環境省コンテンツは政府標準利用規約2.0に基づく。出典を表示し、加工した場合は加工の旨を表示する。
- 気象庁データを将来使う場合も出典を表示し、加工データを国が作成したように示さない。
- 予報・警報を扱う機能では気象業務法上の制約を確認し、独自予報と誤認される表現を避ける。
- APIの数値的なレート上限は公開マニュアルで確認できなかったため、実装前にサービス固有の注意事項を再確認する。
- 暑さ指数情報には年度ごとの運用期間がある。運用期間、仕様書年度、エンドポイントを設定値として記録し、年度切替時に疎通確認する。

## 次Issueの受入条件案

- 上記2データ契約をアプリのドメイン層に実装する
- 環境省Web API・警戒情報CSVのクライアントを分離する
- タイムアウト、20分キャッシュ、期限切れ、欠測、運用期間外をテストする
- 外部通信を使わないfixtureテストと、手動疎通コマンドを用意する
- 出典・時刻・品質を失わずUI層へ渡す
- 公式サービス障害でも経路検索は継続できる
