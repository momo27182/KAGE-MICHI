# 影計算と経路探索

最終更新: 2026-08-11

## 分離した責務

- `BuildingShadowCalculator`: 加工済み建物データと日時から影ジオメトリを生成する。
- `MidpointShadeRoutePlanner`: 加工済み道路グラフと生成済みの影から経路を探索する。
- `PysolarPositionProvider`: 緯度・経度・タイムゾーン付き日時から太陽高度と方位角を求める。

これらはStreamlitや地図表示を読み込まず、それぞれ単独でテストできる。太陽位置を固定値へ差し替えることで、外部時刻に依存しない再現テストも行える。

## 現行アルゴリズム

影計算は建物外形と、建物高さ・太陽位置から平行移動した外形の凸包を作り、全建物分を結合する。太陽高度が0度以下なら影ジオメトリを生成しない。高さが欠損した建物は、加工済みデータのmanifestにある既定値、または10mで補う。

経路探索は道路エッジの中央点が影ポリゴン内にあるかを判定する。日向エッジの距離へ既定で10倍のペナルティを掛け、NetworkXの最短経路探索を行う。接続経路がない場合や開始・終了が同一ノードの場合は`RouteNotFoundError`とする。

## 固定ケースで確認する境界

- 太陽が地平線下なら影なしとなる。
- 建物高さが欠損しても10mとして影を生成できる。
- 接続経路がなければ製品側の例外へ変換される。
- 同一の建物・日時・太陽位置から同一の影を再現できる。
- 同一の道路・影・地点・ペナルティから同一の経路を再現できる。

## 実データ測定

2026-08-11に和歌山駅周辺半径1.7kmの加工済みOSMデータと、`wakayama_station_to_tanakaguchi_summer_afternoon`を使用した。

| 処理 | 結果 |
|---|---:|
| 対象建物 | 7,870件 |
| 影生成対象 | 7,865件 |
| 影計算 | 2.687秒 |
| 経路探索 | 0.239秒 |
| 経路距離 | 1,294.543m |
| 日陰率（中央点判定） | 30.366% |

実行環境やウォームアップ状態で時間は変動する。現時点では経路探索より影ポリゴンの生成・結合が主要な最適化対象である。

## 既知の制約

- 建物高さ欠損は10m固定であり、PLATEAUはまだ利用していない。
- Polygonだけを影生成対象とし、MultiPolygon等は対象外である。
- 凸包による簡易影で、屋根形状、地形、樹木、相互遮蔽は扱わない。
- 道路は中央点だけで判定し、区間内の日陰長や時間変化は評価しない。
- 日向ペナルティは固定倍率で、気温・湿度・風・WBGTは未反映である。
- 計算結果は暑熱曝露を減らすための推定であり、安全を保証するものではない。
